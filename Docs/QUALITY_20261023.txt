CAMERAS AND ACTIONS
TPS aim stays external at72FOV; FPS uses the Ballista sight at65FOV. Default
FOVs are90/95. The external arm stays430cm; animations do not change its length.
Crouch capsule changes are compensated immediately and the visible camera height
eases with a100cm/s limit. Camera collision still shortens the arm near walls;
this prevents seeing through geometry and is not disabled.
CLS receives the visible body's orientation and travel intent while not aiming.
This removes conflicting camera/body yaw intent; aiming retains directional fire.
Held-L3 running keeps9m/s through steering, walking5m/s.
TapB crouches/stands; heldB goes prone; grounded runningB slides then crouches.
Crawl speed120cm/s. A from prone stands first. Airborne input cannot initiate a
ground slide. Native floor/headroom checks remain enabled.
Original Parkour wall-run/wall-jump logic remains. The local action graph uses
owned root-locked melee/wall-jump/crawl clips, plus CLS reload/hit clips. A separate
upper-body slot lets reload coexist with the prone lower body.

Animation limits: original Parkour pack has9 assets and no skeletal clips.
Slide is currently a crouch-pose placeholder; prone uses the owned zombie belly
crawl, blended in/out. Dedicated human slide, prone-entry/exit and wall-run poses
were not found in the audited owned assets. Functional actions are not finished
animation quality. Owner review of turning and transitions remains required.
Selected outfit, skin, body springs, chain and glider motion tuning are preserved.

RGCL LIVE CONTROLS (THE SUPPLIED EDITOR PANEL)
Open Window > ZESP Control Panel during Play. It is an editor tool that changes
runtime gameplay, not an automatic in-game upgrade screen. The local panel's
definition browser now includes project-local item, zombie and wave data assets.
Select DA_AFS_Ballista, DA_CyberZombie or DA_CyberWaves, not the untouched originals.
- Live: Vexa walk/sprint/crouched speed and controller look sensitivity.
- Live: weapon damage, range, cadence, recoil/spread, reload duration via the
  equipped local weapon definition/native weapon. Current magazine is not filled
  merely because a definition is reapplied. Some capacity changes take effect on
  the next reload/equip, following the native weapon implementation.
- Live: zombie run/walk speed, attack cooldown and sight/hearing ranges; attack
  damage/loot settings are read by the native combat/reward paths.
- Starting weapons/ammo/gold: next Play session from DA_CyberWaves.StartingEquipment.
- Wave definitions: applied by the supplied wave state machine at its transition
  boundaries. Existing damaged zombies are not healed by changing health settings.
- Deliberate limits: Vexa still uses Parkour jump/air control, CLS animation and
  AFS cameras. The vendor pawn's animation replacement, FPS-arm and sprint-stamina
  settings are not substituted for these. Death/respawn settings have no effect
  on invulnerable Vexa. The native source's wave damage multiplier is unfinished;
  health/count/speed scaling is active. No blanket 'all vendor settings work' claim.
The pack's M16/pistol/grenade meshes/definitions are installed for later loadout
authoring. This pass configures Ballista tiers and melee; it does not present every
installed gun as a finished Vexa loadout or replace her outfit with vendor armor.
